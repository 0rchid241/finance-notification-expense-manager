# 디자인 시스템 1차안

> 목표: **라이트 모드를 기본으로 하는 깔끔한 개인 금융 앱**. 토스처럼 정보 계층은 단순하게 유지하되, 가계부답게 거래 정보는 높은 밀도로 표현하고, 정합성·사용자 규칙 결과는 작은 상태 Chip으로 강조한다.

이 문서는 기능 구현 과정에서 화면이 개발자 테스트용 UI로 흐트러지지 않도록 하기 위한 1차 디자인 기준이다. 가계부 기본 기능은 빠르게 구현하되, 이후 핵심 기능인 정규화·정합성·사용자 규칙 고도화에도 그대로 재사용할 수 있는 공통 규칙을 정의한다.

---

## 1. 디자인 방향

### 키워드

- Clean
- Financial
- Calm
- Dense enough

### 기본 원칙

- 기본 테마는 **라이트 모드**다.
- 다크 모드는 설정에서 사용자가 ON/OFF 할 수 있다.
- 흰색/밝은 회색 배경을 중심으로 사용한다.
- 카드 남발을 피한다.
- 핵심 숫자와 상태만 강조한다.
- 거래 목록은 카드형보다 **정보 밀도가 높은 Row/List 구조**를 우선한다.
- 상태 색상은 의미가 필요한 곳에만 제한적으로 사용한다.
- 입력 화면과 조회 화면을 섞지 않는다.
- 홈은 요약/조회, 거래는 목록/상세, 규칙은 관리, 설정은 환경 설정 역할로 분리한다.

---

## 2. 화면 구조

하단 네비게이션은 다음 4개 탭으로 고정한다.

```text
홈 | 거래 | 규칙 | 설정
```

### 홈

역할: 이번 달 상태를 한눈에 보는 대시보드.

주요 구성:

- 이번 달 지출 요약
- 지난달 대비 변화
- 지출 / 입금 / 확인 필요 요약
- 주의가 필요한 거래 요약
- 최근 거래 4~5건
- 전체 거래 보기

홈 화면에서는 입력 폼을 직접 노출하지 않는다.

### 거래

역할: 일반 가계부의 메인 거래 내역 화면.

주요 구성:

- 월 선택
- 월간 지출 / 입금 요약
- 필터: 전체 / 출금 / 입금 / 확인 필요
- 날짜별 거래 그룹
- 거래 Row
- 상태 Chip: 중복 의심 / 내부이체 후보 / 규칙 경고
- 거래 상세 화면 진입

### 규칙

역할: 사용자 규칙 관리.

주요 구성:

- 등록된 규칙 목록
- 활성/비활성 토글
- 규칙 추가
- 최소 지원 규칙
  - 일정 금액 이상 지출
  - 상대방 이름 키워드 포함
- 이후 수정/삭제 확장 가능

### 설정

역할: 앱 권한 및 환경 설정.

주요 구성:

- 알림 접근 권한
- 지원 금융앱
- 다크모드 ON/OFF
- 데이터 관리
- 앱 정보

## 3. 컬러 시스템

## 3.1 라이트 모드 — 기본

| 역할 | 색상 | 용도 |
| --- | --- | --- |
| Background | `#F7F8FA` | 앱 전체 배경 |
| Surface | `#FFFFFF` | 카드, 시트, 상단 영역 |
| Surface Secondary | `#F1F3F5` | 필터, 보조 영역 |
| Primary | `#3182F6` | 주요 버튼, 선택 상태 |
| Text Primary | `#191F28` | 제목, 핵심 금액 |
| Text Secondary | `#6B7684` | 설명 |
| Text Tertiary | `#9AA4B2` | 날짜, 보조정보 |
| Divider | `#E5E8EB` | 구분선 |

### 금융/상태 색상

| 상태 | 색상 | 사용 예 |
| --- | --- | --- |
| 출금 | `#F04452` | 출금 금액 |
| 입금 | `#3182F6` | 입금 금액 |
| 성공/정상 | `#00A86B` | 성공 상태 |
| 규칙 경고 | `#F59F00` | 규칙 경고 Chip |
| 중복 의심 | `#F04452` | 중복 의심 Chip |
| 내부이체 후보 | `#6C5CE7` | 내부이체 후보 Chip |

### 색상 사용 원칙

- 거래 전체 배경을 상태 색으로 칠하지 않는다.
- 출금/입금은 **금액 텍스트 중심으로만** 강조한다.
- 정합성/규칙 상태는 작은 Chip으로 표현한다.
- 화면 전체에서 동시에 강한 색상이 너무 많이 보이지 않도록 한다.

### 테마 정책

- 앱 최초 기본값: **라이트 모드**
- 설정에서 다크모드 ON/OFF 가능
- 시스템 테마 자동 연동은 1차 범위에서는 필수 아님

## 4. Typography

종류를 과도하게 늘리지 않는다.

| 용도 | 크기 | 굵기 |
| --- | ---: | --- |
| 화면 제목 | 24sp | Bold |
| 핵심 금액 | 30~32sp | Bold |
| 섹션 제목 | 18sp | SemiBold |
| 거래명 | 16sp | SemiBold |
| 본문 | 15~16sp | Regular |
| 보조정보 | 13~14sp | Regular |
| 상태 Chip | 12sp | Medium |

### 정보 계층 예시

```text
이번 달 지출          15sp
428,300원             32sp Bold
지난달보다 52,000원 적게 사용   14sp
```

핵심 금액이 가장 먼저 보이도록 한다.

---

## 5. Spacing

기본 단위는 **4dp**를 사용한다.

```text
4dp   아주 작은 간격
8dp   아이콘 ↔ 텍스트
12dp  같은 그룹 내 요소
16dp  일반 컴포넌트 간격
20dp  화면 좌우 기본 padding
24dp  섹션 간격
32dp  큰 영역 간격
```

### 화면 기본 여백

- 좌우 padding: `20dp`
- 주요 섹션 간 vertical spacing: `24dp`
- 리스트 Row 내부 세로 padding: `12~16dp`

## 7. 카드 사용 규칙

카드는 정보 그룹을 묶는 용도로만 사용한다.

### 카드 사용 권장

- 홈의 월간 요약
- 홈의 확인 필요 요약
- 규칙 관리의 개별 규칙
- 설정의 그룹 영역

### 카드 사용 지양

거래 하나하나를 전부 큰 카드로 감싸지 않는다.

권장 형태:

```text
쿠팡이츠                    -10,800원
카카오뱅크 · 17:49
──────────────────────────
GS25                         -4,500원
카카오뱅크 · 14:22
──────────────────────────
급여                       +968,006원
카카오뱅크 · 09:00
```

## 8. Status Chip

정합성/규칙 결과는 거래 금액보다 덜 강조되는 작은 상태 Chip으로 표현한다.

예시:

```text
[중복 의심]
[내부이체 후보]
[규칙 경고]
```

### 원칙

- 한 줄 높이의 작은 Chip
- 연한 배경 + 의미 색상 텍스트
- 아이콘은 필요한 경우에만 사용
- 거래 금액보다 시각적 우선순위가 낮아야 함
- 한 거래에 여러 상태가 있을 경우 가로 배치 후 줄바꿈 허용

---

## 9. 버튼

### Primary Button

중요한 행동에만 사용한다.

예:

```text
+ 규칙 추가
```

- Primary Blue 배경
- 흰색 텍스트
- Radius 12dp

### Secondary / Text Action

단순 이동이나 보조 행동은 텍스트 액션으로 표현한다.

예:

```text
전체 거래 보기 >
```

화면마다 채워진 Primary 버튼을 여러 개 두지 않는다.

---

## 10. 입력창

입력 폼은 필요한 화면에서만 노출한다.

- 홈에는 입력 폼을 두지 않는다.
- 규칙 추가 화면/Bottom Sheet 등 명확한 입력 컨텍스트에서만 사용한다.
- Material 3 `OutlinedTextField`를 사용하되 색상, radius, spacing은 디자인 시스템에 맞춘다.

예:

```text
지출 기준 금액
[ 50,000                         ]

알림 메시지
[ 큰 지출이 발생했어요          ]
```

## 12. 재사용 Compose 컴포넌트

초기 UI 개편 시 아래 컴포넌트를 우선 정의한다.

| 컴포넌트 | 역할 |
| --- | --- |
| `AppBottomBar` | 4탭 하단 네비게이션 |
| `MonthlySummaryCard` | 월간 지출/입금 요약 |
| `TransactionRow` | 거래 한 건 표시 |
| `StatusChip` | 정합성/규칙 상태 |
| `RuleCard` | 규칙 목록 |
| `SectionHeader` | 섹션 제목/보조 액션 |
| `SummaryMetric` | 지출/입금/확인 필요 요약 |
| `EmptyState` | 데이터 없음 |
| `SettingRow` | 설정 한 줄 |

공통 컴포넌트를 먼저 만든 뒤 화면을 조립한다. 화면별로 비슷한 UI를 중복 구현하지 않는다.

## 13. 거래 Row 기준

거래 목록은 다음 정보 계층을 기본으로 한다.

```text
쿠팡이츠                         -10,800원
카카오뱅크 · 20:13
[규칙 경고]
```

### 필수 정보

- 거래명/상대방
- 금액
- 출처 금융앱
- 시간

### 선택 정보

- 정합성 Chip
- 규칙 경고 Chip
- 카테고리

잔액, 계좌 끝자리 등 상세 정보는 거래 상세 화면에서 보여주는 것을 우선한다.

## 14. 화면별 구현 최소 범위

가계부 공통 기능에 과도한 시간을 쓰지 않기 위해 다음 최소 범위만 우선 구현한다.

### 홈

- 이번 달 지출
- 이번 달 입금
- 확인 필요 개수
- 최근 거래 5개

### 거래

- 월 선택
- 날짜별 거래 목록
- 전체 / 출금 / 입금 / 확인 필요 필터
- 거래 상세 진입

### 규칙

- 규칙 목록
- 규칙 추가
- 활성/비활성

### 설정

- 알림 접근 권한
- 다크모드
- 데이터 초기화

가계부 기본 UI 구현이 완료되면 장기간 확장하지 않고 다시 프로젝트 핵심인 정규화·정합성·사용자 규칙 고도화로 돌아간다.

## 15. 구현 순서

### 1차 — UI 기반 공사

```text
Theme / Color / Typography
→ AppBottomBar
→ StatusChip
→ TransactionRow
→ 공통 컴포넌트
```

### 2차 — 화면 조립

```text
홈
→ 거래
→ 규칙
→ 설정
```

### 3차 — 검증

```text
실기기 확인
→ 간격/색상/정보 밀도 미세 수정
→ UI 기반 작업 종료
```

## 16. AI/Codex 구현 지침

UI 작업을 AI에게 맡길 때 아래 원칙을 반드시 지킨다.

- "예쁘게 만들어줘"처럼 추상적으로 요청하지 않는다.
- 이 문서의 Color / Typography / Spacing / Radius / Component 규칙을 구현 기준으로 제공한다.
- 한 번에 전체 앱을 재작성하지 않는다.
- 공통 컴포넌트를 먼저 구현한 뒤 화면별로 조립한다.
- 기존 정규화·정합성·규칙 비즈니스 로직을 UI 개편 과정에서 변경하지 않는다.
- 거래 목록은 큰 카드 반복 대신 `TransactionRow`를 사용한다.
- 홈에 규칙 입력 폼을 직접 노출하지 않는다.
- 상태는 큰 경고문 대신 `StatusChip`으로 표시한다.
- 라이트 모드가 기본이며 다크모드는 설정에서 사용자가 선택한다.

## 17. 현재 확정 수준

이 문서는 **1차안**이다.

현재 확정된 항목:

- 4탭 화면 구조
- 라이트 모드 기본 정책
- 다크모드 선택 정책
- 기본 컬러 팔레트
- 타이포 계층
- spacing/radius 원칙
- 거래 Row 중심 구조
- 정합성/규칙 Status Chip 표현
- 공통 컴포넌트 방향

실기기 UI 개편 후 실제 사용감에 따라 색상/간격/타이포 수치는 미세 조정할 수 있다.
