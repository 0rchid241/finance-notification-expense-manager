# Master Roadmap — 금융 알림 기반 개인 지출 관리 시스템

> 목표: **2026-10-31까지 실제 Android 기기에서 핵심 흐름이 끝까지 동작하는 Release Candidate 완성**

이 문서는 프로젝트의 **진행률 기준(Source of Truth)** 이다.  
세부 일정은 `weekly-plan.md`, 설계는 `architecture.md`, 요구사항은 `requirements.md`를 따른다.

## 진행률 계산 규칙

- 전체 진행률은 아래 세부 항목의 **가중치 합계(100%)** 로 계산한다.
- `[x]`는 기본 브랜치에 구현·테스트·문서 등 완료 근거가 확인되는 경우에만 표시한다.
- 단순 파일 생성, 작업 중 브랜치, 미병합 PR, 아이디어만 있는 상태는 완료로 계산하지 않는다.
- 기능 범위가 바뀌면 총합 100%를 유지하도록 가중치를 함께 조정한다.

## M0. 프로젝트 기반 — 5%

- [x] **1%** GitHub 저장소 및 Android 기본 구조 구성
- [x] **1%** Android 프로젝트 실기기 실행 구조 확보
- [x] **1%** Android 로컬 처리 중심 MVP 아키텍처 확정
- [x] **2%** README / 요구사항 / 아키텍처 / 주간 계획 문서화

**완료 기준:** 신규 개발자가 저장소만 보고 프로젝트 목적, 현재 MVP 구조, 실행 단위를 이해할 수 있다.

---

## M1. 원본 금융 알림 수집 — 15%

- [x] **4%** `NotificationListenerService` 등록 및 실제 알림 이벤트 수신
- [x] **2%** package / title / text / postedAt 등 원본 필드 추출
- [x] **4%** Room 기반 Raw Notification 저장소(Entity / DAO / Repository) 및 기본 테스트
- [ ] **1%** 사용자 알림 접근 권한 안내 / 설정 진입 UX
- [x] **2%** 금융 알림 후보 필터 및 null·무의미 알림 처리 정책
- [x] **2%** 실기기 Room 저장 / 동일 이벤트 별도 행 / 앱 재실행 후 영속성 검증

**완료 기준:** 실제 금융 알림이 Android에서 안정적으로 수집되고 원본 데이터가 Room에 보존되며, 이후 정규화 대상과 제외 대상을 구분할 수 있다.

---

## M2. 알림 해석 및 정규화 — 20%

- [x] **3%** Raw Notification 처리 계약 및 상태 전이(`PENDING / PROCESSED / PARSE_FAILED`) 확정
- [x] **3%** 구조화된 금융 거래 모델 및 Room 저장 구조 정의
- [x] **4%** 첫 금융 앱/결제수단 Parser 구현 — 카카오뱅크 입금/출금
- [ ] **3%** 두 번째 이상의 금융 알림 형식 지원 및 Parser 분리 구조 확장
- [x] **2%** 금액 / 상대방 / 계좌 / 잔액 / 거래 유형 / 발생 시각 / 출처 추출
- [x] **2%** 해석 실패·미확정 이벤트 별도 처리
- [x] **3%** 정규화 자동 테스트와 실제 카카오뱅크 샘플 E2E 검증

**완료 기준:** 서로 다른 금융 알림이 공통 구조의 거래 데이터로 변환되고, 해석할 수 없는 알림은 정상 거래로 강제 변환되지 않는다.

---

- [ ] **3%** 거래 상태 모델 정의
- [ ] **4%** 동일 이벤트 재처리 idempotency
- [x] **4%** 동일 실제 거래의 다중 알림 / 중복 후보 판별
- [ ] **4%** 승인 취소 원거래 매칭
- [ ] **2%** 환불 및 기타 상태 전이 처리
- [ ] **3%** 정합성 핵심 케이스 자동 테스트

**완료 기준:** 중복 알림은 거래를 중복 생성하지 않고, 취소·환불 이벤트가 가능한 경우 원거래와 연결되어 일관된 상태를 유지한다.

## 현재 기준 진행률

기본 브랜치에서 확인된 체크 항목 기준: **47%**

> M0 5% + M1 14% + M2 17% + M3 4% + M5 7%.  
> 체감 진척이 아니라 기본 브랜치에 병합된 구현·테스트·실기기 검증 근거가 있는 항목만 반영한다.

## 2026-10-01 확인된 E2E

```text
실제 카카오뱅크 입금/출금 알림
→ NotificationListenerService
→ Raw Room 저장
→ KakaoBankNotificationParser
→ 구조화된 거래 저장
→ Compose 최근 거래 카드 표시
```

실기기에서 입금/출금 2건이 `financial_transactions`에 저장되고 앱 화면에 표시되는 것을 확인했다.

## 백엔드 처리

`backend/`의 Spring Boot 코드는 초기 통신 PoC로 보존한다.
현재 MVP 진행률에는 Android → Backend 연결을 요구하지 않으며, 향후 확장 기능이 필요할 때 다시 사용한다.
