# 요구사항

## 1. 프로젝트 범위

2026년 10월 안에 Android 기기에서 금융 알림을 수집하고, 백엔드에서 정규화·정합성 처리·사용자 규칙 평가를 수행한 뒤
가계부와 피드백으로 확인할 수 있는 동작 가능한 버전을 완성한다.

## 2. 필수 기능

### 알림 수집
- 사용자가 알림 접근 권한을 허용할 수 있어야 한다.
- Android에서 발생한 금융 앱 알림을 감지할 수 있어야 한다.
- 수집 시 앱 패키지명, 제목, 본문, 발생 시각 등 최소한의 원본 정보를 확보한다.

### 정규화
- 지원 대상 금융 앱별 알림 형식을 해석할 수 있어야 한다.
- 알림에서 금액, 가맹점, 거래 유형, 발생 시각, 출처를 추출한다.
- 서로 다른 알림 형식을 하나의 공통 금융 이벤트 형식으로 변환한다.
- 해석할 수 없는 알림은 정상 거래로 강제 변환하지 않고 별도 상태로 관리한다.

### 거래 정합성
- 동일한 실제 거래에서 여러 알림이 발생해도 거래가 중복 생성되지 않도록 한다.
- 승인 취소 또는 환불 알림을 가능한 경우 기존 거래와 연결한다.
- 동일 이벤트가 재전송되어도 결과가 불필요하게 중복되지 않도록 한다.
- 거래의 승인/취소/환불 등 상태를 일관되게 관리한다.

### 사용자 정의 규칙
- 사용자가 카테고리, 기간, 금액 또는 횟수를 기준으로 규칙을 생성할 수 있어야 한다.
- 거래가 반영된 후 활성 규칙을 평가한다.
- 조건이 충족되면 사용자에게 피드백을 생성한다.

### 가계부
- 거래 목록을 확인할 수 있어야 한다.
- 잘못 처리된 거래를 사용자가 확인하고 수정할 수 있는 방향을 고려한다.
- 카테고리별 지출을 확인할 수 있어야 한다.

## 3. 비기능 요구사항
- 핵심 처리 로직은 자동 테스트가 가능하도록 UI와 분리한다.
- 새로운 금융 앱 지원 시 기존 핵심 로직의 수정이 최소화되도록 알림 해석 구조를 분리한다.
- 민감한 원본 알림은 필요 이상으로 저장하지 않는다.
- 서버 통신 실패나 알림 해석 실패가 전체 앱 오류로 이어지지 않도록 한다.

## 4. 이번 버전에서 제외
- iOS 지원
- 모든 금융사 지원
- 오픈뱅킹 연동
- AI/LLM 분석
- 광고/구독 결제
- 외부 공개 API 서비스 운영
- 머신러닝 기반 분류

위 기능들은 핵심 MVP 완성 이후 확장 대상으로 둔다.
